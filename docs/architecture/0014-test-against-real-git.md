# 14. Test against real git with isolated config

- Status: Accepted
- Date: 2026-10-27

## Context

gitdrift's correctness is git's behavior: porcelain output, exit codes,
refusals, prune and ref-lock semantics. Mocking git would test assumptions
instead. Tests also must not read the developer's git config or leak state
between parallel tests.

## Decision

- `internal/gittest` creates throwaway repositories, clones and bare remotes
  in `t.TempDir()`. Each git command it runs, and each `git.Runner` it
  returns, gets an isolated environment: a temporary `GIT_CONFIG_GLOBAL`,
  `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_COUNT=0`, a fixed author, and leaked
  `GIT_*` variables (including `GIT_CONFIG_KEY_*`) removed. No test uses
  `t.Setenv`, so every test can run with `t.Parallel()`.
- Race windows are hit deterministically with git's own hooks: an
  `uploadpack` script that moves a branch during `ls-remote`, a
  `reference-transaction` hook that sleeps during `branch -D`, a
  `post-merge` hook that keeps a merge running while gitdrift quits.
- The suite runs with `-race -shuffle=on`; the workspace tests check for
  leaked goroutines with `goleak`.
- The UI is tested by driving `Update` with a fake backend, with golden files
  regenerated by `go test ./internal/ui -update`, a resize sweep, and one
  end-to-end test (`teatest`) that pulls through the real workspace.
- The git output parsers are fuzzed.

## Consequences

- Tests show what git really does on the machine running them.
- The suite needs git 2.30 or newer and takes about 15 seconds with the race
  detector.
- Only the installed git version is exercised; CI runs on Ubuntu and macOS.
